# 人物卡关系图 · 手动测试用例

> 配合 `npm run dev`，浏览器开 http://localhost:5173。数据落在 `server/data/wewrite.db`（种子小说「示例小说：雨夜便利店」）。
> 自动化冒烟已有 `node scripts/verify-relations.mjs`（API 层 20 项）；本清单覆盖**界面交互**。

建议先准备：在资源管理器选中种子小说，确认侧边栏显示小说标题。

---

## 1. 视图入口

| # | 步骤 | 预期 |
|---|------|------|
| 1.1 | 活动栏应能看到 7 个图标：资源管理器/人物卡/世界观/伏笔/文风/章节细纲/素材库 | 人物卡是**第 2 个**（人形图标） |
| 1.2 | 点击「人物卡」图标 | 侧边栏标题变「人物卡」，右侧主编辑区出现关系图板 |
| 1.3 | 尚未创建任何人物时 | 图板中央显示灰字「还没有人物，点侧边栏 ＋人物 创建」 |
| 1.4 | Ctrl+Shift+P 命令面板输入「人物卡」 | 出现「切换到人物卡」命令，回车可跳转 |

## 2. 人物增删改

| # | 步骤 | 预期 |
|---|------|------|
| 2.1 | 点工具栏「＋人物」，只填「姓名=林晚」保存 | 侧边栏列表出现林晚；图板中央出现节点「林晚」（普通小圆点） |
| 2.2 | 再建陈默/老周/阿水三个 | 4 个节点分布合理，名字在圆点下方，节点可被力导向推开不重叠 |
| 2.3 | 点列表里「林晚」行 | 林晚被选中（图上高亮 + 列表行高亮），下方出编辑表单 |
| 2.4 | 编辑表单改「身份/背景=深夜便利店店员」+ 勾选「主要人物」保存 | 图板林晚节点变**大圆点 + 强调高亮**；列表显示 ★ 徽标 |
| 2.5 | 再勾选陈默为「主要人物」 | 陈默也变大节点 |
| 2.6 | 取消林晚的主要勾选，保存 | 林晚回普通小圆点，★ 消失 |
| 2.7 | 点林晚编辑，删「陈默」 | 陈默从列表与图板消失；若有连到陈默的关系，图上自动消失 |
| 2.8 | 姓名留空点保存 | 不保存，无报错 |

## 3. 关系增删改

| # | 步骤 | 预期 |
|---|------|------|
| 3.1 | 点工具栏「＋关系」，人物A=林晚、B=陈默，关系=夫妻，备注=高中同学 | 图上林晚↔陈默出现一条灰线，中点标「夫妻」 |
| 3.2 | 再建 林晚—老周（师徒）、老周—阿水（酒友） | 共 3 条边，标签各在中点 |
| 3.3 | 图上点「夫妻」连线（点线上任一位置） | 连线变选中高亮，侧边栏出关系编辑表单（A/B 下拉预填林晚/陈默） |
| 3.4 | 表单改关系=「情侣」，保存 | 连线标签更新为「情侣」 |
| 3.5 | 再选该关系，点「删除」 | 连线消失，侧边栏表单收起 |
| 3.6 | 重新建一条「林晚—阿水」关系后点取消 | 表单消失，图不变，无残留边 |

## 4. 连线模式（图上直接连）

| # | 步骤 | 预期 |
|---|------|------|
| 4.1 | 工具栏点「连线」 | 按钮变强调色（btn-primary），侧边栏提示「连线模式：在图上依次点两个人物建立关系」 |
| 4.2 | 图上依次点「林晚」再点「阿水」 | 弹出关系表单，A/B 预填 林晚/阿水；连线模式自动退出 |
| 4.3 | 填关系=「同事」保存 | 图上出现林晚—阿水连线 |
| 4.4 | 再进连线模式，连「林晚」→「林晚」（同一个人） | 第二次点同一节点不触发建关系（不产生 A==B 的边） |
| 4.5 | 连线模式下按 Esc | 退出连线模式，回到普通选择 |
| 4.6 | 连线模式下再点「连线」 | 取消连线模式 |

## 5. 图板交互

| # | 步骤 | 预期 |
|---|------|------|
| 5.1 | 拖动一个节点 | 节点跟随鼠标移动，松手停在原位；边跟着拉长（弹簧感） |
| 5.2 | 滚轮向上/下 | 图板以鼠标位置为中心缩放 |
| 5.3 | 空白处按住拖拽 | 整张图平移（pan），背景出现平移光标 |
| 5.4 | 点节点 A 再点另一节点 B | 每次点击：B 被选中高亮，A 取消高亮，侧边栏切到对应人物表单 |
| 5.5 | 打开「只看主要」开关 | 图上只剩 main 节点（两端都在场的边才显示）；侧边栏列表同步只剩主要人物 |
| 5.6 | 关闭「只看主要」 | 全部节点与边恢复，之前选中的节点仍选中 |

## 6. 图板与编辑器同屏共存（左右分栏）

> 规则：切到「人物卡」视图即显示图板，固定在主编辑区**右侧**（约 340px），与章节编辑器**左右分栏共存**、互不遮盖。切到其它视图时图板隐藏，编辑器占满。

| # | 步骤 | 预期 |
|---|------|------|
| 6.1 | 资源管理器点开一个章节，再点「人物卡」 | 右侧出现图板，左侧仍显示章节编辑器，两者同屏；tab 保留在标签栏 |
| 6.2 | 在编辑器里继续写章节 | 图板同时可见，不遮挡编辑、不影响输入 |
| 6.3 | 点标签栏里该章节 tab | 编辑器仍是章节内容，图板保持显示 |
| 6.4 | 关闭该 tab | 图板保持显示，左侧编辑器区回到空态提示 |
| 6.5 | 切到「资源管理器」视图（无 tab） | 图板隐藏，编辑器占满主区 |
| 6.6 | 切回「人物卡」视图 | 图板恢复右侧显示，节点布局重排 |
| 6.7 | 拖动图板与编辑器之间的分隔条（鼠标悬停变 ↕↔ 双向箭头） | 图板宽度随拖动变化（200–720px），编辑器相应伸缩；松手后刷新浏览器，宽度保持 |

## 7. 数据落盘

| # | 步骤 | 预期 |
|---|------|------|
| 7.1 | 建好人物+关系后，看小说目录 `server/data/novels/*/.docs/人物卡/` | 每个人物一个 .md，front-matter 含 `main: "1"`（主要人物） |
| 7.2 | 看 `.docs/人物关系/人物关系.md` | front-matter 的 `edges` 是 JSON 数组，结构与图上一致 |
| 7.3 | 刷新浏览器（F5） | 人物、关系全部还原；选中态清空 |
| 7.4 | 重启 dev server 后再进人物卡 | 数据不丢 |
| 7.5 | 资源管理器里**不**应出现「人物关系」文档入口 | 关系只从图板/侧边栏管理，不重复入口 |

## 8. 边界情况

| # | 步骤 | 预期 |
|---|------|------|
| 8.1 | 没有选中任何小说时进人物卡 | 侧边栏显示「先在资源管理器中选择一部小说」；图板空态 |
| 8.2 | 只有 1 个人物 | 节点孤立显示，不报错 |
| 8.3 | 手改 `.docs/人物关系/人物关系.md` 的 edges 为坏 JSON | 图板按空关系处理，不白屏 |
| 8.4 | 手改 edges 引用不存在的人物 id | 该边被过滤不显示，不报错 |
| 8.5 | 删除一个被多条关系引用的人物 | 相关边全部消失，其余人物/关系完好 |
| 8.6 | 「只看主要」打开且无主要人物 | 提示「还没有标为『主要』的人物」 |
